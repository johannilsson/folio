## Ranked findings

All five findings from the previous review still hold with the same evidence. They are listed here in the same order so the ranking can be tracked.

### 1. The page saves the whole sidecar from its own copy, which can drop an agent's concurrent writes (needs design)
- *Evidence:* editor mutations in `annotations.ts` / `raw-annotations.ts` rebuild a `Sidecar` from the module-level `currentSidecar` and call `putFolio`, which replaces the file (`server.rs:172`, `Bridge.swift`). Unchanged.
- *Impact:* a click in the window between an agent's append and the page's `folio:changed` refresh deletes the agent's new annotations or replies.
- *Direction:* per-operation writes applied against the file on disk (as `/api/accept` does), or a revision check on the PUT with an id-level merge. The bridge contract changes either way (`Bridge.swift`, `e2e/fixtures.ts`, `BRIDGE.md`).

### 2. Editor sidecar writes skip the validated, atomic save (small → [#22](https://github.com/johannilsson/folio/issues/22))
- *Evidence:* `put_folio` still calls `tokio::fs::write` on the raw body (`server.rs:186`), and `Document.writeSidecar` still uses `Data.write(to:)` without `.atomic` (`Document.swift:62`).
- *Impact and direction:* as in the previous review. The issue is open and untouched.

### 3. The annotation UI is written twice, once per editor mode (needs design)
- *Evidence:* `annotations.ts` and `raw-annotations.ts` still carry parallel card, overlay, floater and reply code. Source-mode accept still sends `putFile` and `putFolio` as two writes.
- *Impact and direction:* as in the previous review. Open design question: should source-mode accept go through `/api/accept`, or stay client-side to keep CM6 undo?

### 4. The resolution outcome (`resolved_as`) is an untyped string, and its values depend on which path resolved it (small → [#23](https://github.com/johannilsson/folio/issues/23))
- *Evidence:* still `Option<String>` (`sidecar.rs:72`) with different values per call site.
- *Impact and direction:* as in the previous review. The issue is open and untouched.

### 5. A set with a custom `--root` reads a different sidecar from the one the per-file CLI writes (needs design)
- *Evidence:* `commands::folio_path` still always uses `detect_root` (`src/commands/mod.rs:28-31`); sets use `resolve_root`. The skill still documents the gap as an exception.
- *Impact and direction:* as in the previous review.
