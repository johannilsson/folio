## Ranked findings

### 1. A set with a custom `--root` is still read from a different sidecar by the app than by the CLI and MCP tools (needs design)
- *Evidence:* unchanged. `set::resolve_root` honours `SetFile.root` (`src/set.rs:141`); `location::folio_path` (`location.rs:22`) and `ffi.rs:87` use `detect_root` only. `SKILL.md:240` still documents the exception.
- *Impact:* an agent following the set's reported sidecar and one using the tools write to two files; the human sees one. Every new entry point has to know the exception. Open PRs [#117](https://github.com/johannilsson/folio/pull/117) and [#118](https://github.com/johannilsson/folio/pull/118) add set features (group order, folders, version 2) on top of it.
- *Direction:* decide whether a custom root is a feature. If yes, one file→root lookup in `location.rs` that consults sets, used by CLI, FFI and MCP; if no, drop `--root` and `SetFile.root`. Best decided before wiki mode lands, since it changes the set format. Fourth review.

### 2. Inline-card room is state kept beside the text, and each surface has to remember to reset or shift it (needs design)
- *Evidence:* `InlineRoom` (`Annotations/TextSurface.swift:222`) holds `[characterIndex: height]`, a second copy of where cards are, in the text view's layout. `PreviewView` and `SourceEditorView` each own one and decide when to `reset()` (`PreviewView.swift:102, 373`, `SourceEditorView.swift:96`) or `shift(map)` (`SourceEditorView.swift:204`; the preview has no shift). The first bug is already open: a reload or a change of suggestion previews drops the room and the scroll position jumps ([#116](https://github.com/johannilsson/folio/pull/116), unbuilt and untested). `setInlineRoom`, `row`, `lineMark`, `lineTop` and `inlineColumn` are written twice with small differences (`AnnotationSurface.swift:80`).
- *Impact:* any new way the text can change (a reload, previews, wiki pages from [#118](https://github.com/johannilsson/folio/pull/118) that follow the pages without a reload) must update this map correctly or cards overlap text or the page jumps. This is the "view keeps its own copy that can drift" pattern the sidebar bug was.
- *Direction:* derive the room from the annotations and heights on each layout (anchors are already reported on every layout) instead of keeping and shifting it; or give `InlineRoom` one owner with a single `textChanged(map)` entry. The row-for-index rule can be a FolioKit function with a unit test. Add a self-test check for the scroll offset after an outside change.

### 3. `mcp.rs` holds the protocol, the annotation tools and the client-config writers in one file (needs design)
- *Evidence:* 1297 lines, 78 functions, 4 commits since 2026-10-26. `annotate` and `commands/annotate.rs` still each do validate → build → anchor-check → create dir → save. [#113](https://github.com/johannilsson/folio/pull/113) adds another tool and a `changes` module that both the CLI and MCP call, which is the right shape; the tool plumbing goes in the same file.
- *Impact:* each new tool or opt-in rule edits the one file that also holds unrelated config-file code; CLI and MCP can diverge in validation.
- *Direction:* split into `mcp/` modules (protocol, tools, connect) and give the engine one `add_annotations(sidecar, content, items)`. Do it before more tools arrive.

### 4. The self-test is the largest module and grows with each feature (needs design)
- *Evidence:* `macos/Sources/Folio/SelfTest/` is 3062 lines (was 2853); `SelfTest+Inline.swift` added 208 this week, with checks of card placement that the new `CardLayoutTests` and `PreviewTextTests` partly cover. FolioKit has 6 test files.
- *Impact:* UI changes edit a long, timing-sensitive file whose failures show only in macOS CI; several open PRs ([#110](https://github.com/johannilsson/folio/pull/110), [#116](https://github.com/johannilsson/folio/pull/116), [#117](https://github.com/johannilsson/folio/pull/117)) note that Swift was not built where they were written.
- *Direction:* as before, keep moving layout and state rules into FolioKit unit tests and the self-test for wiring only.

### 5. The sidebar badge parses the sidecar by hand (small → [#107](https://github.com/johannilsson/folio/issues/107))
- *Evidence:* `Document.pendingCount()` (`Document.swift:80`) still uses `JSONSerialization`. The fix is in draft PR [#110](https://github.com/johannilsson/folio/pull/110).
- *Impact:* a second, untested reader of the format.
- *Direction:* merge [#110](https://github.com/johannilsson/folio/pull/110).
